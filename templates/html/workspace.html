                                        跨网联通安全性说明与警示
                                        
    
                                            
  1. 当前做法：本功能采用 Ngrok 建立公网隧道（brew install ngrok/ngrok/ngrok），由商业公司维护、有稳定性保障，对外默认提供 HTTPS，优于免费公益中继（如 LocalTunnel）。
    2. 
                                            
  2. 访问鉴权：每次开启隧道都会自动生成 16 位随机密码，并以 --basic-auth mockuser:<随机密码> 注入 Ngrok。未携带正确账号密码的外部请求会被 Ngrok 直接拒绝（401），无法触及你的本地 Mock 服务。
    3. 
                                            
  3. 密码传递方式：随机密码与公网地址被编码进本机二维码（Mac ↔ 你自己的手机）闭环传递，密码不进入聊天工具、邮件，也不嵌入可被转发的链接。在「人手一 Mac、本地自用」的场景下，密码不会离开你的设备生态，泄露风险极低。
    4. 
                                            
  4. 安全性评估：相比「裸奔穿透」与免费公益服务，本方案在稳定性、子域抢占防护、访问鉴权三方面均有实质性提升；配合二维码本机闭环传递随机密码，可进一步避免密码外泄。对临时、非敏感的跨网调试而言，是足够安全且便捷的做法。
    5. 
                                            
  5. 仍非绝对安全 / 使用边界：① 流量经由 Ngrok 服务器中转，TLS 在其侧终止，请勿经此传输核心保密数据；② 免费版子域会自动复用、可能被回收或与他人冲突，请勿将其当作永久地址；③ 该方案定位为临时、非敏感的跨网调试，非生产级。
    6. 
                                            
  6. 即用即开原则：调试完成后请立即切回「局域网直连」模式以关闭公网通道；并避免将二维码/密码转发至群聊或截图外传。每次启动都会重新生成新的随机密码。
    7.

路径映射转发 (Path Mapping)

                                    
将 /mock/{path} 请求自动转发到真实目标地址

                                

                                ▾
                            
                            

                                

                                    

                                        当 App 因 SDK 限制无法修改 Header 时，会把真实请求改写到 /mock/{path}?...。配置映射后，服务器会把匹配的 /mock/sa 转发到真实目标（如 https://sc-sa.dramaboxdb.com/sa），原 query 参数会自动拼接到真实 URL。

                                            AP 隔离与 VPN 冲突

代理冲突: 手机需关闭 Clash、Shadowrocket 等可能接管流量的代理软件。
